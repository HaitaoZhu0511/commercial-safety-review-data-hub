# 国内外审核与风控公开实践对标

> 调研日期：2026-09-24。本文件只总结公司官网、官方帮助中心、透明度中心、产品文档和公开政策。它不描述任何公司的内部组织、未公开阈值、模型权重或处置规则。

## 阅读边界

为避免把公开产品能力误写成“内部审核线真相”，本文把信息分为三层：

| 证据等级 | 定义 | 本文写法 |
| --- | --- | --- |
| A：官方政策或透明度报告 | 公司正式发布的规则、报告、System/Model Report | 可以描述其公开机制与指标名称 |
| B：官方产品或帮助文档 | 云产品、广告平台、开发者文档公开的能力 | 可以描述产品支持的输入、流程和控制点 |
| C：架构推断 | 从 A/B 级事实推导出的中台建设建议 | 必须明确标注“建议”或“推断”，不能说成公司内部实现 |

“Instagram/Ins”不是独立公司，而是 Meta 的产品。本文将 Meta 作为公司治理主体，同时单独说明 Instagram 的产品侧控制面。

## 核心结论

1. **国内商业审核更强调经营链路联动**：广告主、商家、资质、商品、素材、落地页、投放、交易和售后往往需要串联判断。
2. **OpenAI、Anthropic 更强调模型能力风险**：除了输入输出内容，还要评估越狱、工具调用、Agent 自主动作、模型能力阈值和部署保障。
3. **Meta/Instagram 更强调超大规模 UGC 治理**：政策、自动发现、人工复核、降权/删除/限制、申诉恢复和透明度指标形成长期闭环。
4. **共同趋势是从“审核结果”走向“风险运营系统”**：规则版本、模型版本、证据、人工决定、申诉、上线实验、事后风险和复盘必须连接起来。

## 一线审核线通常在做什么

公开材料能够支持的共性工作链路是：

```text
政策与准入
  → 主体/资质/账户核验
  → 内容与行为风险识别
  → 规则、模型与上下文编排
  → 自动处置或人工审核
  → 上线后持续监控
  → 举报、申诉与复核
  → badcase、漂移、实验与策略迭代
```

这条线不应被理解为一个“审核模型”。它至少包含政策、算法、审核运营、数据分析、工程平台、法务合规、业务安全和申诉治理等角色。

## 阿里巴巴：交易与经营对象联动治理

### 官方公开事实

- [淘宝规则中心](https://rulechannel.taobao.com/)公开平台规则入口，说明平台治理依赖可发布、可查询的规则体系。
- [淘天知识产权保护平台](https://ipp.alibabagroup.com/)提供权利保护入口，表明知识产权投诉、权利人材料和平台处置是电商治理的重要组成。
- [Alibaba Cloud Content Moderation](https://www.alibabacloud.com/help/en/content-moderation/latest/what-is-content-moderation)公开支持图片、视频、文本、音频等多模态风险识别，并强调规则、模型和行业场景的组合。

### 对审核中台的可验证启示

- 审核对象不能只有广告素材，还应覆盖商家、品牌、商品、资质、价格表达、落地页、交易和售后信号。
- 知识产权案件需要独立的权利人、权属证明、被投诉对象、反通知、复核和处置证据链。
- 规则变更应带适用对象、行业、地域、生效时间和历史版本，才能解释“同一商品为什么前后结论不同”。

### 不能据此推断的内容

公开页面不能证明阿里内部具体组织结构、线上阈值、拦截比例、模型架构或审核人力配置。

## 字节跳动：内容分发、商业投放与主动治理并行

### 官方公开事实

- [巨量引擎](https://www.oceanengine.com/)公开覆盖广告投放、品牌、搜索、电商、本地生活、线索等多种营销场景，意味着商业审核需要面对多投放位、多目标和多内容形态。
- [巨量引擎帮助中心](https://support.oceanengine.com/)公开广告账户、投放和规则相关帮助内容，可作为广告主准入、资质、素材和投放链路的政策入口。
- [火山引擎内容安全文档](https://www.volcengine.com/docs/6256/65101)体现字节系公开的内容安全能力入口。
- [TikTok 透明度中心](https://www.tiktok.com/transparency/en/community-guidelines-enforcement)公开内容治理与执行报告；其公开页面还展示自动移除和用户举报前主动发现等指标。TikTok 属于字节系国际产品，但不能直接等同于抖音国内审核机制。

### 对审核中台的可验证启示

- 需要同时建模“内容是否违规”和“内容是否适合分发/商业放大”，两者不能共用一个二元标签。
- 投放前审核之外，还需要监控投放后的落地页变化、隐蔽跳转、评论/举报、流量异常和账号网络行为。
- 自动化不能只报通过率，应同时报告主动发现率、举报前处置率、恢复率、误伤和风险存续时长。

## 腾讯：多模态识别、场景策略与人机协同

### 官方公开事实

- [腾讯云天御内容安全平台](https://cloud.tencent.com/product/tms)公开支持文本、图片、音频和视频，并描述“模型、样本库、规则库”的场景策略组合以及人机协同/机审架构。
- [腾讯营销](https://e.qq.com/ads/)公开覆盖广告营销场景，说明商业内容还要结合广告账户、目标、版位和投放链路理解。
- [腾讯 ESG 与行动页面](https://www.tencent.com/en-us/esg.html)是腾讯公开治理、隐私和社会责任材料的入口。

### 对审核中台的可验证启示

- 信号层应统一文本、图像、音频、视频、AIGC 检测、账号和行为信号，而不是为每个业务重复建设孤岛。
- 策略层需要允许业务按场景组合规则、样本库和模型，但组合结果必须保存版本与理由。
- 面向社交、内容、小游戏/小程序和广告等不同入口时，应复用风险本体，同时隔离业务权限和处置动作。

## OpenAI：使用政策、模型保障与 Agent 动作安全

### 官方公开事实

- [OpenAI 使用政策](https://openai.com/policies/usage-policies/)定义产品和 API 的使用边界。
- [Moderation API](https://developers.openai.com/api/docs/guides/moderation)提供文本与图像风险分类；官方文档明确说明该端点免费，并指出它不是处理已知或疑似 CSAM 的专用替代方案。
- [Preparedness Framework](https://openai.com/index/updating-our-preparedness-framework/)把前沿模型能力评估与部署保障联系起来。
- [Agent Builder Safety](https://developers.openai.com/api/docs/guides/agent-builder-safety)强调 Prompt Injection、不可信输入、结构化数据、工具审批和 Guardrail 等 Agent 风险控制。

### 对审核中台的可验证启示

- 风险对象从“内容”扩展为 `prompt + context + retrieved_data + tool_call + side_effect + output`。
- 模型输出风险分数不能直接授权高影响动作；支付、封禁、发布和外发数据等动作应经过确定性权限检查或人工审批。
- 评测集需要同时测拒答不足和过度拒答，避免安全指标提高但正常业务大面积不可用。

## Anthropic：能力阈值、部署保障与越狱防护

### 官方公开事实

- [Responsible Scaling Policy](https://www.anthropic.com/responsible-scaling-policy)将模型能力、风险阈值、评估和部署保障放在同一治理框架中；公开页面会随版本更新并保留变更说明。
- [Constitutional Classifiers](https://www.anthropic.com/news/constitutional-classifiers)公开讨论针对通用越狱的分类器、红队测试、过度拒答和算力成本之间的权衡。
- [Anthropic Transparency Hub](https://www.anthropic.com/transparency)汇总模型能力、安全评估、部署保障和模型报告。

### 对审核中台的可验证启示

- 不应只在模型发布后看事故；应在能力接近风险阈值前触发专项评估与更强保障。
- 越狱防护要同时监控攻击成功率、正常请求拒绝率、延迟与成本，不能只追求单一拦截率。
- 风险报告应记录评估范围、已知局限、残余风险、例外批准与保障负责人。

## Meta 与 Instagram：大规模 UGC、分级处置与透明度指标

### 官方公开事实

- [Meta Community Standards](https://transparency.meta.com/policies/community-standards/)提供 Facebook、Instagram 等产品适用的社区标准入口。
- [Community Standards Enforcement Report](https://transparency.meta.com/reports/community-standards-enforcement/)公开按风险类别观察内容处置量、风险流行率、主动发现、申诉和恢复等指标。
- [Meta 对降权内容的说明](https://transparency.meta.com/features/approach-to-ranking/types-of-content-we-demote/)表明平台处置不只有删除，还包括降低分发等分级动作。
- Instagram 适用 Meta 的社区标准，并在产品侧提供举报、账号状态、推荐资格和申诉等入口。

### 对审核中台的可验证启示

- 决策层必须把 `policy_decision` 和 `enforcement_action` 分开：同一政策结论可对应删除、降权、警告、限制推荐、限制功能或账号措施。
- 质量看板不能只统计“处理了多少”，还要看风险流行率、主动发现率、申诉率、恢复率与执行准确性。
- 推荐系统、广告系统和社区治理可共用风险信号，但必须分别保存处置范围和影响面。

## 推荐补入本项目的能力

### 1. 统一风险对象模型

在原有商业内容对象上新增：

```text
AIRequest → Prompt → Context → RetrievedDocument → ModelVersion
          → ToolProposal → Approval → ToolExecution → SideEffect
          → Output → UserFeedback → Incident
```

### 2. 三类发布门禁

- **规则/Prompt 门禁**：语法、冲突、离线回放、影子、灰度、回滚。
- **模型门禁**：能力评估、安全评测、过度拒答、群体切片、残余风险。
- **Agent 门禁**：工具白名单、参数 Schema、最小权限、人工审批、金额/影响上限、Kill Switch。

### 3. 四组不能被平均值掩盖的指标

- 安全：严重风险漏放、攻击成功率、风险存续时长。
- 可用：误杀、过度拒答、正常任务完成率、申诉恢复。
- 运营：人审率、SLA、单案成本、专家队列积压。
- 治理：证据完整率、版本可追溯率、审批绕过、例外过期率。

### 4. 申诉与透明度

申诉结果要区分原审核错误、新证据、政策变化、模型漂移和执行错误；对外透明度可以发布聚合指标，但不得泄露可被攻击者利用的阈值或特征组合。
