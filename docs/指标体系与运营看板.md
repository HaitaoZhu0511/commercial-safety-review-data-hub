# 指标体系与运营看板

## 指标设计原则

- 指标同时覆盖规模、效率、质量、风险、纠错、体验和商业影响。
- 每个指标必须有分母、时间锚点、成熟窗口、数据新鲜度、Owner 和版本。
- 自动通过率、拒绝率和收入不能单独作为优化目标。
- 审核员指标使用最小样本量和难度校正，不公开个人排名。
- 申诉翻案要按“原判错误、证据新增、政策变化、系统缺陷”拆分。

## 看板分层

### 管理驾驶舱

- 提交量、审核通过量、商业消耗和风险调整收益。
- 严重风险漏放曝光量与风险存续时间。
- 自动化率、人工队列规模、SLA 达成率与单位审核成本。
- 申诉量、翻案率和重大政策/模型变更影响。

### 审核运营

- 各队列进入、完成、积压、年龄分布和预计清空时间。
- 按语言、地域、行业、内容类型和复杂度拆分处理时长。
- 初审/复审分歧、抽检通过率和证据缺失率。
- 高风险案件升级、超时和交接次数。

### 规则与模型

- 规则命中量、独立贡献、重叠、误杀、漏放和申诉翻案。
- 模型 Coverage、延迟、超时、校准、Precision/Recall 和 Cohort 偏差。
- 版本前后通过率、队列量、SLA、风险和商业影响差异。
- Shadow/Canary/Active 各阶段门禁状态。

### 政策质量

- 理由代码分布、政策冲突、无法判断和专家升级比例。
- 不同审核员、队列和语言的一致性与分歧原因。
- 政策更新后的培训覆盖、错误恢复时间和重复咨询主题。

## 核心指标定义示例

| 指标 | 公式 | 必要切片 | 风险提示 |
| --- | --- | --- | --- |
| 自动化率 | 自动完成案件 / 成熟案件 | 路由、行业、地域、内容类型 | 高不等于好，需同时观察漏放与翻案 |
| SLA 达成率 | SLA 内决定案件 / 应完成案件 | 队列、优先级、语言、班次 | 暂停等待补件时间需单独扣除 |
| 申诉翻案率 | 原决定被推翻申诉 / 成熟申诉 | 原决定、政策、规则、审核渠道 | 证据新增不等于原判错误 |
| 风险漏放率 | 抽检/事后确认违规的通过案件 / 抽检通过案件 | 严重度、行业、曝光区间 | 必须使用风险分层抽样权重还原 |
| 误杀率 | 抽检/申诉确认安全的拒绝案件 / 可验证拒绝案件 | 政策、规则、模型、账户阶段 | 申诉人群有选择偏差 |
| 风险存续时间 | 首次曝光至有效处置时长 | 风险级别、发现来源 | 对未曝光案件不适用 |
| 审核分歧率 | 复审与初审不同案件 / 有效复审案件 | 政策、难度、内容类型 | 不应用作单一人员绩效 |
| 证据完整率 | 满足证据合同的决定 / 全部决定 | 自动/人工、系统版本 | 字段非空不等于证据有效 |

## 风险调整商业指标

建议使用护栏式表达，不把安全转换为单一货币值：

```text
安全通过消耗 = 通过且成熟窗口内未确认严重违规的商业消耗
可恢复误杀损失 = 因错误拒绝或过度限制造成、经复核可确认的机会损失
风险调整收益看板 = 收益指标 + 严重风险曝光 + 误杀 + 申诉 + SLA 并列展示
```

禁止用一个加权总分掩盖严重安全事件。
