# 商业化安全审核中台设计

## 1. 业务边界

首版覆盖商业广告和推广内容，不承担通用社区内容治理的全部职责。审核对象包括：

- 广告主、代理商、商业账户和关联主体。
- Campaign、广告组、定向、出价和投放位。
- 文案、图片、视频、音频、直播切片和互动组件。
- 落地页、跳转链、下载包、商品/SKU、价格、资质和承诺。
- 支付、账单、优惠、退款和疑似欺诈信号。

## 2. 审核状态机

```text
submitted
  → snapshot_ready
  → signals_ready
  → policy_evaluated
      ├─ auto_approved → enforced → monitored
      ├─ auto_rejected → enforced → appealable
      └─ queued → assigned → reviewing
                      ├─ second_review
                      ├─ expert_review
                      └─ decided → enforced → appealable
  → appealed → appeal_review → upheld / overturned / remanded
  → closed
```

状态变化使用事件驱动，禁止直接覆盖历史。每个事件至少包含 `event_id`、`case_id`、前后状态、操作者、发生时间、原因和相关证据。

## 3. 决策分层

| 层 | 产物 | 示例 |
| --- | --- | --- |
| 信号 | 可观测事实与分数 | OCR 命中、URL 跳转、资质过期、模型置信度 |
| 政策 | 业务与法规要求 | 某行业必须提供特定资质 |
| 规则 | 可执行条件 | 行业=X 且资质缺失 → 进入资质复核 |
| 路由 | 处理方式 | 自动通过、自动拦截、普通人审、专家审 |
| 决定 | 对内容的判断 | 通过、拒绝、限制、需修改 |
| 处置 | 对系统状态的动作 | 停投、限流、下架、账户限制、证据保全 |

决定与处置必须分离。同一个“拒绝”决定在测试、影子和生产环境可以对应不同处置；人工审核员也不应天然拥有资金冻结或账号永久封禁权限。

## 4. 队列与路由

路由输入包括严重度、置信度、内容类型、行业、地域、账户历史、预计曝光、商业价值、语言、政策技能和 SLA。推荐队列：

- `standard_review`：常规商业内容。
- `regulated_industry`：医疗、金融、博彩、酒类等受监管行业。
- `minor_safety`：可能涉及未成年人。
- `fraud_and_deception`：欺诈、仿冒、虚假承诺和恶意跳转。
- `high_reach_priority`：预计曝光或消耗较高的紧急案件。
- `appeal_review`：与初审人员隔离的申诉队列。
- `quality_sampling`：按风险分层抽检自动和人工决定。

## 5. 规则发布

`draft → syntax_validated → offline_replayed → approved → shadow → canary → active → rolled_back / retired`

每次发布记录规则正文哈希、政策版本、测试集版本、Owner、审批人、预估影响、影子指标、灰度比例和回滚版本。高风险政策需要双人审批。

## 6. 模型接入

模型注册表记录任务、输入模态、标签、训练数据范围、版本、阈值、校准、适用语言/地域、已知限制、评测集和部署端点。模型输出统一为：

```json
{
  "model_id": "creative-risk-text",
  "model_version": "example-1.0.0",
  "label": "misleading_claim",
  "score": 0.82,
  "threshold_version": "example-v3",
  "explanation_refs": ["span:18-31"],
  "status": "complete"
}
```

阈值是路由配置，不应硬编码在模型服务中。模型超时、缺失模态或不支持语言时必须返回显式状态，禁止默认为安全。

## 7. 证据协议

一项决定至少关联：内容快照哈希、政策/规则版本、模型与阈值版本、命中信号、审核人/自动系统身份、理由代码、决定时间、处置结果和申诉关系。敏感原文与分析特征分离保存，按角色控制访问并设置保留期限。

## 8. MVP 服务边界

- Intake API：接收审核对象引用和业务上下文。
- Snapshot Service：冻结内容、落地页和资质版本。
- Feature Gateway：编排 OCR/ASR/视觉/URL/主体信号。
- Policy Service：政策目录、规则包、发布和回放。
- Decision Orchestrator：组合信号并产生路由。
- Review Service：队列、分配、初审、复审和 SLA。
- Evidence Service：不可变决策事件和证据清单。
- Appeal Service：申诉、补充材料、复核与翻案原因。
- Analytics Layer：指标、看板、实验和规则效果归因。
