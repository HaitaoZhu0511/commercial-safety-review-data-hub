# 数据治理与合规边界

## 数据分级

| 等级 | 示例 | 默认访问 |
| --- | --- | --- |
| L0 公开 | 已公开政策编号、聚合指标 | 项目成员 |
| L1 内部 | 规则元数据、模型版本、队列指标 | 业务与数据团队 |
| L2 敏感 | 未公开素材、主体资质、申诉材料、审核备注 | 指定审核与合规角色 |
| L3 高敏 | 身份证件、支付信息、未成年人信息、执法协查 | 专项授权、强审计、最短保留 |

## 最小化原则

- 分析表优先使用稳定伪名 ID，不复制证件、手机号、支付账号和完整地址。
- OCR/ASR 原文与抽取标签分离；普通分析只访问标签和证据引用。
- 审核界面按政策需要展示字段，避免“为了方便”展示完整主体档案。
- 导出默认聚合；明细导出需要目的、范围、保留期和审批。

## 访问控制

授权输入使用 `principal + action + resource + context`：

- Principal：审核员、专家、策略运营、数据分析、模型工程、申诉人员。
- Action：查看、领取、决定、复审、导出、发布规则、回滚、执行处置。
- Resource：项目、队列、案件、证据、规则包、模型版本、数据集。
- Context：地域、班次、案件严重度、双人复核状态、紧急授权和设备可信度。

默认拒绝，管理权限和业务决定权限分离。紧急访问需要时效、原因和事后复核。

## 保留与删除

- 按数据类型、地域、案件状态和法定义务设置保留策略。
- 审计事件可以长期保留摘要和哈希，但不表示原始敏感内容永久保存。
- 删除请求需要传播到快照、特征、索引、缓存、数据集和导出副本。
- 法律保全与正常删除使用独立状态，且必须有授权和到期机制。

## 模型和数据集治理

- 训练样本必须记录来源、许可、政策版本、标签人和质量状态。
- 申诉、用户举报和审核反馈先进入隔离区，不能自动进入训练集。
- 对语言、地域、行业、账户阶段和内容类型做分层评测。
- 模型卡记录适用范围、限制、阈值、校准、已知偏差和回滚条件。
- 生产输入和输出日志先脱敏，再进入调试与评测系统。

## 防滥用边界

公开仓库不提供真实规则阈值、特征权重、黑白名单、模型绕过方法或攻击样本。对外报告使用聚合数据并设置最小样本量；内部查询也遵循用途限制和审计。
