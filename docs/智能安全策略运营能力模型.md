# 智能安全策略运营能力模型

本文件把“智能安全策略运营”岗位描述转成可以落地到数据中台的职责、资产、流程和指标。截图仅作为需求输入；岗位文字不代表本项目与招聘公司存在关系。

## 岗位目标

策略运营不是手工维护黑名单，而是对一条风险链路负责：

```text
识别风险 → 定义政策 → 设计信号 → 评估策略 → 灰度处置
         → 监控结果 → 复盘 badcase → 修订策略与数据
```

最终交付物不是一句“模型准确率提升”，而是：

- 可解释、可版本化的政策与策略资产；
- 可重放的规则、Prompt、Agent Workflow 和模型组合；
- 可验证的离线评测、影子结果、A/B 实验与上线归因；
- 可追溯的处置、申诉、翻案和复盘闭环。

## 六类核心职责

| 职责 | 关键工作 | 标准产物 | 验收指标 |
| --- | --- | --- | --- |
| 风险定义 | 风险分类、严重度、场景与处置映射 | Risk Taxonomy、Policy、Reason Code | 分类覆盖率、政策歧义率 |
| 策略开发 | 规则、模型阈值、Prompt、RAG、Agent 流程 | Versioned Strategy Package | Eval 通过率、变更可追溯率 |
| 评测实验 | Golden Set、红队集、影子、A/B | Eval Report、Experiment Card | 召回、误杀、过度拒答、置信区间 |
| 上线运营 | 灰度、门禁、监控、回滚 | Release、Approval、Kill Switch | 风险漏放、SLA、回滚时间 |
| badcase 归因 | 漏放、误杀、分歧、申诉与漂移 | Root Cause、Owner、Fix SLA | 重复问题率、修复周期 |
| 跨团队落地 | 算法、工程、产品、法务与业务协作 | RFC、数据契约、验收清单 | 里程碑、证据完整度、复用率 |

## 策略资产目录

### 传统商业审核资产

- 主体和行业准入规则；
- 营业、行业、品牌与知识产权资质；
- 素材、文案、图片、音视频和落地页策略；
- 商品、价格、功效宣称和营销承诺；
- 账户历史、支付异常、投诉和处罚；
- 投放后的跳转、举报、曝光和风险存续。

### 大模型与 Agent 资产

- System Prompt 与 Policy Prompt；
- Prompt Injection/Jailbreak 检测策略；
- RAG 数据源白名单、来源和信任等级；
- Tool Schema、工具白名单与最小权限；
- 高影响动作审批和额度限制；
- 输入、推理摘要、工具提议、审批、执行结果与副作用日志；
- 模型、Guardrail、Embedding、Reranker 和知识库版本；
- 红队集、Golden Set、对抗样本和多语言边界样本。

## Prompt 与 Agent 策略开发规范

### 1. Prompt 不是散落配置

每个 Prompt 版本至少记录：

```json
{
  "prompt_id": "commercial_review_router",
  "version": "3.2.0",
  "policy_version": "2026-09",
  "model_allowlist": ["model-family-a"],
  "input_schema": "review-context-v2",
  "output_schema": "decision-proposal-v3",
  "eval_suite": "commercial-safety-golden-v5",
  "owner": "safety_strategy",
  "release_mode": "shadow"
}
```

Prompt 的输出应是结构化“决定建议”，不能把自由文本直接转成处罚动作。

### 2. RAG 内容默认是不可信数据

- 检索文档中的“忽略上文”“调用工具”等文本只能作为待审核数据，不能提升为系统指令。
- 保存文档来源、抓取时间、内容哈希、权限、地域和保留期限。
- 高风险回答必须能定位到证据片段；证据缺失时降级到人工复核或保守模式。
- 用户反馈和申诉材料进入训练集前需脱敏、去投毒、去重和人工抽检。

### 3. Agent 动作分层

| 动作等级 | 示例 | 默认控制 |
| --- | --- | --- |
| L0 只读 | 查询政策、生成摘要 | 审计日志、字段最小化 |
| L1 可逆 | 创建草稿、加标签、生成工单 | Schema 校验、频率限制 |
| L2 有业务影响 | 暂停投放、限制推荐 | 双重确认、范围和时限限制 |
| L3 高影响 | 封禁、资金、外发敏感数据 | 人工审批、职责分离、强制回滚方案 |

模型永远不能仅凭自然语言输出绕过确定性权限系统。

## badcase 归因树

```text
错误决定
├─ 输入问题：快照错误 / OCR-ASR 失败 / 证据缺失
├─ 政策问题：边界模糊 / 地域冲突 / 更新不同步
├─ 规则问题：逻辑错误 / 优先级冲突 / 例外遗漏
├─ 模型问题：漂移 / 多语言差异 / 对抗攻击 / 校准失效
├─ Prompt 问题：指令冲突 / 输出不稳定 / 过度拒答
├─ RAG 问题：召回错误 / 过期文档 / 注入 / 权限越界
├─ Agent 问题：工具误选 / 参数错误 / 审批绕过 / 重试放大
├─ 人审问题：政策理解 / 疲劳 / 技能路由 / 利益冲突
└─ 执行问题：处置未生效 / 范围错误 / 回滚失败
```

每个 badcase 必须有 `root_cause`、`evidence`、`affected_versions`、`impact_scope`、`owner`、`fix_due_at` 和 `regression_case_id`。

## 漂移监控

至少同时监控四类漂移：

- **输入漂移**：语言、行业、内容形态、流量来源和攻击模板变化；
- **概念漂移**：政策含义、法规和平台边界变化；
- **模型漂移**：模型或供应商版本变化造成分数和拒答行为变化；
- **流程漂移**：人审分歧、队列积压、工具失败和处置延迟变化。

漂移告警不得直接等于事故结论，应先确认数据成熟度、抽样偏差和上游埋点变化。

## A/B 与上线归因

安全策略不能只比较实验组的拦截率。推荐最小指标集：

| 指标组 | 指标 |
| --- | --- |
| 安全 | 严重风险漏放、攻击成功率、风险曝光、风险存续 |
| 可用 | 误杀、过度拒答、任务完成率、申诉恢复 |
| 商业 | 安全通过消耗、误杀损失、延迟、转化影响 |
| 运营 | 人审率、队列 P95、SLA、专家审占比、单案成本 |
| 公平 | 地域/语言/行业/人群切片差异及最小样本量 |

实验必须记录样本单元、随机化层级、成熟窗口、停止规则、护栏和回滚条件。严重风险护栏越界时，不得等待统计显著性再回滚。

## 团队协作与职责分离

| 角色 | 负责 | 不应独立完成 |
| --- | --- | --- |
| 政策/法务 | 风险定义、地域规则、申诉原则 | 直接修改线上阈值 |
| 策略运营 | 策略设计、评测、监控、归因 | 单人创建并激活高风险规则 |
| 算法 | 模型、校准、评估和局限说明 | 用模型分数定义最终政策 |
| 工程 | 编排、权限、审计、稳定性 | 在无策略版本时隐式改变判断 |
| 审核运营 | 队列、培训、质检、复审 | 删除原始决定或覆盖证据 |
| 数据分析 | 指标、实验、因果分析 | 用未成熟标签宣布策略成功 |
| 业务产品 | 场景、影响和体验目标 | 以收入覆盖严重风险护栏 |

## 30/60/90 天建设计划

### 0—30 天：统一事实

- 建立 Risk Taxonomy、Reason Code 和处置等级；
- 统一任务、决定、证据、申诉和版本 ID；
- 建立基线看板和 badcase 归因模板；
- 盘点 Prompt、模型、规则、知识库和工具权限。

### 31—60 天：建立评测和发布门禁

- 建立脱敏 Golden Set、多语言边界集和攻击集；
- 接入离线回放、影子运行和差异分析；
- 增加过度拒答、提示注入和工具越权评测；
- 配置审批、灰度、Kill Switch 和回滚演练。

### 61—90 天：形成运营闭环

- 把申诉、举报、抽检和线上事故回流到评测集；
- 建立规则/Prompt/模型/Agent 版本效果归因；
- 建立风险存续、透明度和公平性看板；
- 让每个线上事故自动生成回归 Case，而不是只写复盘文档。

## 常见反模式

- 把“召回率提高”当成完整上线结论；
- 用自动化率替代风险质量；
- Prompt 在线热改但没有版本和回放；
- Agent 能调用高影响工具但没有独立权限层；
- 把用户反馈直接加入训练集；
- 人工决定覆盖原记录，导致无法审计；
- 只看总体指标，不看高风险、地域、语言和行业切片；
- 把公开公司材料解释为其内部真实阈值或组织设计。
